1. Executive Summary & The 60-Second Elevator Pitch

This project is an end-to-end, multi-agent AI decision-support platform designed to solve the critical problem of schedule slippage, supply bottlenecks, and budget inflation across large-scale infrastructure capital programs (highways, bridges, rail networks, airports).

The 60-Second Interview Pitch (Memorize This!)
"Large infrastructure projects routinely suffer from catastrophic delays and cost overruns because project telemetry is deeply fragmented across isolated systems: scheduling in Primavera P6, materials in ERPs, site labor on daily logs, finances in accounting ledgers, and legal rights locked in contracts.

I built the Infrastructure Project Delay & Cost Overrun Intelligence Agent to bridge these silos. Operating on real telemetry across 100 projects and 12,600+ activities, the system detects delays, traces Critical Path propagation, identifies operational root causes (such as warehouse stockouts or contractor labor productivity deficits), calculates financial exposure, retrieves exact contract penalty clauses via local RAG, and recommends prioritized interventions through an interactive 11-tab Streamlit dashboard."

2. The Business Problem in Mega-Infrastructure

In construction programs costing hundreds of crores, project managers often discover delays only after a milestone has already been missed. The fundamental issue is not simply that activities take longer than planned; it is that leadership lacks a unified, cross-domain forensic view:

  • The Schedule Disconnect: A schedule shows a 20-day slip, but does not indicate whether it affects the Critical Path (delaying the whole project) or whether buffer float absorbs the delay.
  • The Root-Cause Disconnect: Traditional tools cannot cross-reference whether an excavation delay was caused by adverse weather, a contractor under-deploying laborers, or a vendor delivering defective steel.
  • The Commercial Disconnect: When a supplier delivers 3 weeks late, project managers rarely have instant access to the governing contract clause (e.g. Clause 8.4 Liquidated Damages) to seek financial recovery before warranties expire.

4. Data Engineering, Preprocessing & Quality Assurance

Production-grade AI systems depend entirely on data integrity. The ingestion layer (src/data_processing/) enforces strict rules:

4.1 Encoding Resilience (Handling Real-World Corruptions)

Real-world construction CSVs contain non-standard character encodings. For example, Road Constuction Delay Survey.csv contained Windows CP1252 directional quotation marks (byte 0x92) that instantly crash standard UTF-8 readers with a UnicodeDecodeError. We built an automated fallback parser in loader.py: 

# Safe Multi-Encoding Loader Pipeline
def _read_csv_safe(self, fpath: Path, **kwargs) -> pd.DataFrame:
    try:
        return pd.read_csv(fpath, encoding="utf-8", **kwargs)
    except UnicodeDecodeError:
        try:
            return pd.read_csv(fpath, encoding="cp1252", **kwargs)
        except Exception:
            return pd.read_csv(fpath, encoding="latin-1", **kwargs)

4.2 Automated Data Quality Auditor (98.0 / 100 Health Score)

Before running any business logic, DataQualityChecker (quality.py) conducts an automated five-point audit:

  1. Referential Integrity: 100% of foreign keys in labor_assignments, cost_ledger, and boq cleanly map to valid parent activity IDs in activities.csv (zero orphan records).
  2. Date Sanity: Validates that planned finishes occur after planned starts, and completed tasks have actual finishes after actual starts.
  3. Financial Sanity: Asserts non-negativity across baseline costs, actual costs, and ledger entries.
  4. Missing Finish Date Logic: Confirms that 64.9% missing actual finishes are expected behavior representing in-progress or not-started activities evaluated against the cutoff date, rather than data corruption.
  5. Out-of-Scope File Exclusion: Identified that Phase-3 tracker.xlsx was an unrelated IT CRM file ("DeepHealth Gleamer-to-Nova Salesforce migration") and safely excluded it to prevent data pollution.

5. Deterministic Analytics Engines & Mathematical Formulas

Architectural Rule of Truth
Never use a Large Language Model for deterministic arithmetic.
All dates, float, durations, burn rates, and variance metrics are calculated using pure, deterministic Python code (Pandas/NumPy). The AI/RAG layer is reserved strictly for language understanding and evidence synthesis.

5.1 Schedule & Critical Path Engine (schedule_engine.py)

  • Completed Activity Delay: $$\text{Finish Delay (Days)} = \text{Actual Finish Date} - \text{Planned Finish Date}$$ (Positive = Delayed; Negative/Zero = On-Time or Ahead of Schedule)
  • In-Progress Overdue Delay (Cutoff Date = August 20, 2026): $$\text{Overdue Days} = \text{Cutoff Date} - \text{Planned Finish Date} \quad (\text{if } \text{Planned Finish} < \text{Cutoff Date})$$
  • Critical Path Impact Alert: $$\text{Critical Path Impact} = (\text{Total Float} \le 0 \lor \text{is\_critical} = \text{True}) \land (\text{Delay Days} > 0)$$ When triggered, the engine recursively queries dependencies.csv to identify downstream successor activities whose start dates are compromised.

5.2 Procurement & Material Shortage Engine (procurement_engine.py)

  • Warehouse Stockout Deficit: $$\text{Deficit Units} = \text{Reserved Quantity} - \text{Closing Stock} \quad (\text{when } \text{Closing Stock} < \text{Reserved Quantity})$$
  • Supplier Shipment Defect Rate: $$\text{Defect Rate (\%)} = \frac{\text{Rejected Quantity}}{\text{Received Quantity}} \times 100$$ Shipments with defect rates $> 5.0\%$ or quality status $\ne \text{'ACCEPTED'}$ trigger a material quality alert.

5.3 Cost Variance & Daily Burn Rate Engine (cost_engine.py)

  • Cost Variance (CV): $\text{Cost Variance} = \text{Actual Cost} - \text{Baseline Cost}$
  • Daily Actual Burn Rate: $$\text{Daily Burn Rate} = \frac{\text{Actual Cost}}{\max(1, \text{Actual Duration Days})}$$
  • Potential Delay Financial Exposure: $$\text{Delay Exposure} = \text{Delay Days} \times \text{Daily Burn Rate}$$ Calculates ongoing site holding costs (equipment rentals, idling labor, overheads) during the delay window.

5.4 Contractor Labor Productivity Engine (contractor_engine.py)

  • Required Productivity Pace: $$\text{Required Rate} = \frac{\text{Remaining Work Quantity}}{\text{Days to Deadline}}$$
  • Productivity Deficit: $$\text{Productivity Deficit} = \text{Required Rate} - \text{Actual Measured Rate}$$ A positive deficit indicates the contractor's current crew is mathematically incapable of hitting the deadline without additional resources.

6. Legal RAG Document Intelligence Engine

When an infrastructure milestone slips, commercial teams need to know their legal standing. We engineered a 100% local Retrieval-Augmented Generation (RAG) engine (src/rag/contract_rag.py):

6.1 Architecture & Local Vector Indexing

  • Corpus: 180 structured clauses from contract_clauses.csv combined with 30 raw text contracts (CONTRACT-001.txt to CONTRACT-030.txt) chunked by clause section headers.
  • Embedding / Vectorization: Uses **TF-IDF with unigram and bigram tokenization** and **Cosine Similarity**: $$\cos(\theta) = \frac{\mathbf{q} \cdot \mathbf{d}}{\|\mathbf{q}\| \|\mathbf{d}\|}$$
  • Zero Cloud Latency & Zero Cost: Runs completely offline in memory, eliminating expensive cloud API tokens, rate limits, and private contract data leaks.
  • Anti-Hallucination Guardrail: Implements a hard relevance threshold ($\text{Score} \ge 0.20$). If a user asks about non-existent topics (e.g. software licenses), the engine immediately returns "Insufficient data: No relevant contractual clauses found" rather than hallucinating terms.

6.2 Verifiable Legal Clause Grounding (Clause 8.4)

When a supplier delivery delay occurs, the RAG engine retrieves Clause 8.4 (Delay and Liquidated Damages):

Retrieved Verbatim Evidence: CONTRACT-001, Clause 8.4
"Where delay is attributable to the supplier, contractual delay remedies may apply after the contractual grace period."
Applicability: Liquidated damages remedies active. Cites contract ID, page number, and section.

7.1 Conflict Resolution Logic (Supervisor)

The Supervisor acts as the chief arbiter. For example:

  • Discrepancy 1 (Cost vs. Schedule): If an activity has delay_days = 0 but exhibits a high cost overrun, the Supervisor resolves that the overrun is driven by unit rate inflation or equipment intensity rather than schedule slippage.
  • Discrepancy 2 (Procurement vs. Status): If warehouse stock is depleted but the activity is COMPLETED, the Supervisor determines the shortage threatens upcoming successor tasks rather than the finished activity.

8. Risk Classification & Predictive Forecasting Models

  • Multi-Factor Risk Scoring (0–100 Points): Schedule Delay (up to 30 pts) + Critical Path Impact (up to 25 pts) + Material Shortages (up to 15 pts) + Labor Deficits (up to 15 pts) + Cost Variance (up to 15 pts).
    Classified into CRITICAL ($\ge 70$), HIGH ($\ge 45$), MEDIUM ($\ge 25$), and LOW ($< 25$).
  • Earned Value Extrapolation (SPI / CPI): For activities with $> 5\%$ progress, forecasts total completion duration and final cost using Schedule Performance Index ($SPI = \text{Actual Progress} / \text{Planned Progress}$) and Cost Performance Index ($CPI$).
  • Machine Learning Baseline Classifier: Implemented a Scikit-learn Logistic Regression baseline model in risk_engine.py trained on completed historical activities to predict whether an activity will suffer delay $> 5$ days based on baseline duration, cost, and float.

11. Top Technical Interview Questions & Word-for-Word Answers

Q1: "Did you use an LLM to calculate schedule delays and cost overruns?"
Model Answer: "No, and that was a conscious, foundational architectural decision. In civil engineering and financial accounting, calculations must be 100% reproducible, auditable, and deterministic. LLMs are probabilistic models that can hallucinate figures and struggle with calendar arithmetic.

Therefore, I built dedicated Python analytics engines using Pandas and NumPy for all date logic, Critical Path float, inventory deficits, and cost variance. I used AI and RAG strictly where language understanding is required—specifically semantic search over legal contracts, cross-domain conflict resolution, and natural-language executive briefings."
Q2: "What is the Critical Path Method (CPM), and why is it important in your system?"
Model Answer: "The Critical Path is the longest sequence of dependent activities from project start to finish that dictates the minimum project duration. Activities on the critical path have a Total Float of zero, meaning they have zero buffer time.

If a non-critical activity slips by 5 days, buffer float absorbs it without impacting the handover date. But if a critical path activity slips by even 1 day, the entire multi-crore program completion slips by 1 day. My Schedule Engine evaluates Total Float and traces downstream successor links in dependencies.csv to immediately alert leadership when a critical path activity is threatened."
Q3: "How does your RAG system work without using expensive cloud APIs like OpenAI?"
Model Answer: "I built a local semantic retrieval engine using TF-IDF vectorization with unigram and bigram n-grams paired with Cosine Similarity. It indexes 180 clauses and 30 full contract documents in memory.

This provides three major advantages: first, zero external API costs; second, complete data privacy because confidential legal agreements never leave the premises; and third, sub-20ms retrieval speed. Furthermore, I enforced a strict relevance threshold of 0.20 to eliminate hallucinations—if a query falls outside the contract repository, the engine returns 'Insufficient data' instead of guessing."
Q4: "How do you distinguish correlation from causation when diagnosing a delay's root cause?"
Model Answer: "Just because a supplier delivery was delayed doesn't mean it caused the activity delay. My RootCauseInvestigationEngine enforces three strict validation hurdles:
1. Relational Linkage: Was the late material actually assigned to that specific activity in the Bill of Quantities?
2. Temporal Alignment: Did the stockout or defect occur before or during the scheduled execution window?
3. Alternative Explanations: It cross-checks contractor labor productivity and predecessor delays.
Only when all relational keys and timestamps align does it assign 'HIGH' confidence. If evidence is ambiguous, it returns 'Probable Root Cause' with 'MEDIUM' confidence or explicitly outputs 'Root cause not established'."
Q5: "Why did you implement Human-in-the-Loop in your recommendation engine?"
Model Answer: "The platform is designed strictly as an executive decision-support system, not an autonomous agent. In mega-infrastructure programs, actions like issuing formal supplier default notices, deducting liquidated damages, or altering contractual milestones carry significant legal and financial liability.

Therefore, every recommendation explicitly flags whether human approval is required, identifies the specific authorized stakeholder (e.g. Commercial Lead, Project Director), and outlines the expected benefits and implementation risks before any action is executed."
